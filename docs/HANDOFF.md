# Онлайн-школа: запуск и передача

Реализовано 29.10.2026. Исходники сайта находятся в `myspanish.space/myspanish.space`, общие школьные компоненты — в `stylist-svelte/modules/prototype/prototype-school`, испанские композиции и авторский демоконтент — в `stylist-svelte/modules/business/spanish`.

## Локальный запуск

Нужны Node.js **24.11+** и Yarn **4.13**. Запускать из каталога приложения:

```powershell
cd D:\2026\cloudflare\myspanish.space\myspanish.space
yarn install --immutable
yarn dev
```

Открыть **http://localhost:5176**. Из корня всего workspace также работает существующий shortcut `yarn myspanish`. Vite использует strictPort: если 5176 занят уже работающим экземпляром, откройте его вместо второго запуска.

Первый запрос создаёт схему и development-данные. Внешние ключи почты, оплаты и видеосервиса не нужны. Для принудительной первоначальной подготовки есть `yarn db:school:init`; для одной схемы без тестовых аккаунтов — `yarn db:school:migrate`.

Данные сохраняются **на сервере**, не в localStorage:

| Файл/каталог | Содержимое |
|---|---|
| `.school-data/site.sqlite` | настройки и воронка заявок |
| `.school-data/school.sqlite` | курсы, модули, уроки, задания, назначения, результаты, расписание, библиотека, импорт |
| `.school-data/pd.sqlite` | имена, контакты, сессии, хеши паролей, тексты ответов/проверок, внутренние заметки |
| `.school-data/files` | собственные материалы и копии разрешённых источников по checksum |
| `.school-data/uploads` | закрытые вложения учеников |

Каталог меняется через `SCHOOL_DATA_DIR`; пример — `.env.example`. Все эти данные исключены из Git. Для резервной копии остановите сервер и скопируйте **весь** каталог трёх баз и файлов вместе. Не копируйте отдельную активно изменяемую SQLite-базу как согласованную резервную копию школы.

## Тестовые роли

На **/login** в development доступны карточки:

- **Администратор:** настройки, пользователи, семейные связи, назначение преподавателей, все курсы и заявки, импорт.
- **Преподаватель:** связанный ученик Аня, демогруппа, свои программы и назначенные заявки.
- **Другой преподаватель:** другой ученик Лев, без доступа к чужим работам.
- **Аня:** назначен демонстрационный курс из трёх уроков.
- **Лев:** другой ученик, курс по умолчанию не назначен — для проверки отказов доступа.
- **Родитель Ани / родитель Льва:** только соответствующий связанный ребёнок.

Эти имена — демонстрационные. В development можно также войти по обычному логину/паролю после задания данных в карточке ученика. Стандартных production-паролей нет. Новые ученики, созданные из заявки в development, тоже доступны в тестовом переключателе.

Родитель в минимальной семейной модели **читает** обучение и работы детей. Прохождение упражнений, отметка урока и отправка ответа выполняются из student-аккаунта. Каждая подмена `child`, идентификатора работы или файла проверяется на сервере.

## Что работает

- Публичная главная, направления с фильтрами, карточка программы, пример урока, FAQ, контакты, бесплатная библиотека и помеченные черновиками юридические страницы.
- Сохранение заявки с валидацией контакта/согласия, honeypot, лимитом отправок и idempotency key. Ученик создаётся из заявки; преподаватель назначает курс. В production новые заявки сначала доступны администратору, который назначает ответственного преподавателя.
- Личный кабинет: назначенные курсы, модули и уроки, прогресс, задания и сроки, история попыток, комментарии, расписание, материалы, избранное, профиль и часовой пояс.
- Рабочий кабинет: ученики, доступ и его отзыв, группы, назначения группе, заметки, курсы/модули/уроки, черновик и публикация, предпросмотр, очередь проверки с фильтрами, заявки, библиотека и настройки.
- Семь упражнений: один ответ, несколько ответов, пары, пропуск, порядок, карточки и свободный ответ. Закрытые ответы проверяются сервером; правильные ключи не выдаются в learner DTO. Свободный ответ попадает на проверку через механизм домашней работы. Повторение карточек сохраняет самооценку, а не выдуманный балл знания.
- Черновик ДЗ → отправка → возврат → новая попытка → проверено; история сохраняется. Преподавателю черновик и его вложения не выдаются до отправки. Родитель видит работы своего ребёнка.
- Закрытые файлы выдаются через проверку сессии и доступа. Загрузка ученика: PDF, PNG, JPEG, MP3, WAV, до 10 МБ; проверяются расширение и сигнатура/MIME, суточный лимит 200 МБ. HTML/SVG/исполняемые не принимаются.
- Поиск и серверная пагинация библиотеки по 25 записей. Изменение безопасной темы массово не меняет права. Открытие материала требует проверки и разрешения; для нового разрешения на публичное использование нужен администратор и запись основания.

Старые публичные лендинги перенаправлены в новые разделы, чтобы не выводить неподтверждённые сведения о преподавателе, возрасте, ценах и отзывах. Старая `/admin` остаётся отдельным контуром Telegram/quiz; школьная админка находится на `/staff`.

## Добавить курс и урок

1. Войти преподавателем/администратором → **Курсы → Создать курс**. Заполнить название и описание, сохранить.
2. Добавить модуль. В секции модуля создать урок: название, цель, блоки, упражнения, домашнее задание и необязательный срок UTC.
3. Блоки редактируются в **JSON**. Это рабочий структурированный редактор, не визуальный WYSIWYG:

```json
[
  { "type": "text", "text": "¡Hola! — Привет!" },
  { "type": "attachment", "fileId": "идентификатор-материала" }
]
```

Доступны `text`, `image`, `audio`, `video`, `attachment`. Для файлов нужен ID библиотеки; произвольные публичные URL не заменяют проверку доступа. В поле ID материалов перечислите привязанные материалы через запятую. Файл остаётся один, связей с уроками может быть несколько.

Пример упражнения:

```json
[
  {
    "id": "hello",
    "kind": "single",
    "prompt": "Как поздороваться?",
    "options": [{ "id": "a", "text": "Hola" }, { "id": "b", "text": "Adiós" }],
    "answer": ["a"],
    "explanation": "Hola — приветствие."
  }
]
```

Другие `kind`: `multiple`, `matching`, `gaps`, `ordering`, `cards`, `text`. Полные примеры всех семи типов — в `stylist-svelte/modules/business/spanish/data/json/spanish-beginner-demo/index.json`.

Для пар задаются `pairs: [{id,left,right}]`, где `right` у matching — ID варианта; `answer` содержит правильные ID в порядке строк. У cards `right` — перевод. Для gaps сейчас один пропуск и один строковый ключ; у ordering ключ — перестановка всех ID слов. Свободный текст и карточки не требуют автоматического ключа. Сервер отвергает неправильные схемы и неизвестные ключи.

4. Установить порядок урока и публикацию. Заметки преподавателя — отдельное скрытое поле. Предпросмотр не меняет прогресс.
5. Опубликовать сам курс, затем в карточке ученика назначить доступ; либо назначить курс группе. Преподаватель управляет своими курсами и связанными учениками; администратор может передать редактирование курса и связать преподавателя с учеником в настройках.
6. Для обычного входа ученика задать логин и пароль в его карточке. Передать их вручную; отправка письма не имитируется. Смена пароля отзывает старые сессии.

## Подключить архив

Исходный учебный архив и его `scripts/spanish-folder-status/README.md` в проверенной копии не обнаружены. Его содержимое не прочитано. Импортёр проверен на собственных CSV/файловых fixtures, а не на историческом архиве из 4892 файлов. Перед подключением реального источника прочитать его README, связанные отчёты и реестр и проверить соответствие колонок.

Указать `ARCHIVE_SOURCE_ROOT` в локальном `.env`, например путь к доступной копии архива, и перезапустить сервер. Этот путь — **только источник для чтения**. Производные файлы сохраняются отдельно в каталоге данных сайта. Если переменная не задана, импортируются только метаданные, а отсутствующие вложения честно помечаются.

Пример реестра: `database/example-registry.csv`. Поддерживаются UTF-8/BOM, CSV с запятой/точкой с запятой/табуляцией, кавычки и многострочные поля. Колонки: `relative_path` (`path`, `путь`, `относительный путь`, `исходный путь`), `title` (`название`, `имя файла`), `description` (`описание`), `processed` (`обработано`), `topic` (`тема`), `level` (`уровень`). Неизвестные форматы реестра необходимо сначала явно сопоставить с этой схемой; автоматическое толкование произвольных отчётов не обещается.

Через интерфейс: **администратор → Библиотека → Импортировать реестр** → выбрать CSV и устойчивый source ID → посмотреть отчёт → подтвердить конкретную порцию. В UI показываются первые 100 записей предпросмотра; обработка порции охватывает весь CSV. Лимит: 8 МБ / 10 000 записей за порцию, физический файл до 100 МБ.

Через CLI:

```powershell
yarn archive:preview database/example-registry.csv school-archive
yarn archive:import database/example-registry.csv school-archive <digest-из-предпросмотра>
```

`ARCHIVE_SOURCE_ROOT` для CLI задаётся как переменная процесса. CLI не загружает `.env` сам; при необходимости используйте `node --env-file=.env --experimental-strip-types scripts/school/import.ts preview ...`.

Identity: source ID + нормализованный относительный путь. Исходное написание пути сохраняется отдельно. Физические файлы сопоставляются по безопасному realpath внутри корня, вычисляется SHA-256. Совпадающие имена не объединяются; одинаковое содержимое использует общий file/blob с сохранением записей происхождения. Повторный импорт обновляет запись, сохраняет редакторские описания, права и статусы, не создаёт копий материала. Источник не перемещается, не переименовывается; ZIP не распаковываются.

Признак «обработано» сохраняется отдельно: полнота остаётся неизвестной. Права, редактура и публикация независимы. По умолчанию импортированное закрыто и является черновиком. Работы учеников и технические/персональные разделы исключаются. Twinkl, Reading A–Z и прочие издательские материалы не открываются по факту наличия файла. Администратор подтверждает основание прав и проверку отдельно.

## Проверки

```powershell
yarn check
yarn test
yarn test:e2e
yarn build
yarn build:node
yarn test:production
node docs/school-composition/verify.mjs
```

На этой машине браузерные тесты используют установленный Chrome. В другой среде можно установить Chromium командой `yarn playwright install chromium`, задать `PLAYWRIGHT_CHANNEL=chromium` и запустить `yarn test:e2e`. E2E поднимает отдельный сервер **5187** и собственную БД в `.test-data`; production smoke — временный сервер **5186** и временные данные. Рабочая демонстрационная БД тестами не очищается.

Проверены: 24 unit/integration-теста, браузерные публичные страницы и размеры 360/390/768/1440, меню/Escape/возврат фокуса, пары с клавиатуры, порядок кнопками Enter и touch, полный цикл заявки/назначения/проверки, редактор/предпросмотр и импорт через UI. Скриншоты реально открывались для визуальной проверки. Артефакты: `test-results/manual-review` (исключены из Git).

Node production smoke проверяет собранный сервер, настоящий парольный вход, защищённый staff и отсутствие тестового выбора роли. `verify.mjs` проверяет только историческую карту композиции и адреса компонентов, не подменяет тесты приложения.

Во время разработки исправлены найденные тестами ошибки записи упражнений, потери раннего клика до гидрации, назначения неправильного направления и доступа преподавателя к черновикам. Исходная build-папка была недоступна для очистки текущему пользователю, поэтому используется `.svelte-kit-school`; конфиги синхронизированы с этим путём. Node 24 помечает встроенный SQLite как experimental. При первом изолированном browser-run эмулятор Cloudflare пытался писать Wrangler log вне разрешённого workspace и удерживал build-папку. Ненужная для Node/SQLite-разработки эмуляция bindings отключена; конфигурация production Cloudflare-сборки сохранена. В отдельном E2E outDir остаётся информационное предупреждение о пути tsconfig; основной yarn check проходит без предупреждений. Удалённые миграции и деплой не запускались.

## Node-развёртывание без тестовых аккаунтов

```powershell
yarn build:node
yarn user:create
yarn start:node
```

`user:create` интерактивно спрашивает имя, логин, роль и скрытый пароль от 12 символов; для первого пользователя выбрать `admin`. По умолчанию создаётся отдельная **.school-production**, а не development-база. Пароль хранится в salted scrypt-хеше. Для автоматизации поддерживается JSON через stdin с `--stdin`; не сохранять реальные пароли в репозитории или журнале команд.

`start:node` запускает готовый `build-node` на `127.0.0.1:3000`, включает SQLite и лимит тела 12 МБ. Настройки — в `production.env.example`; в production Node не подхватывает `.env` автоматически. Можно запустить `node --env-file=production.env scripts/school/start-node.mjs`, предварительно создав приватный конфиг с реальными параметрами (не коммитить его).

Для другого каталога задавать одинаковый `SCHOOL_DATA_DIR` при создании владельца и при запуске. Перед переносом копировать `build-node`, `scripts/school/start-node.mjs`, `database/migrations`, необходимые runtime dependencies и конфигурацию. Исходная установка использует соседнюю библиотеку через Yarn portal: для сборки из исходников нужен весь соответствующий workspace с инициализированными модулями.

Для публичного сервера нужны выбранный хост, постоянный приватный диск, TLS/reverse proxy и правильный `ORIGIN=https://...`; настройку хоста и публикацию владелец выполняет отдельно. Не использовать demo-базу: runtime откажется запускать её как production. Самостоятельное восстановление пароля по почте не подключено; пароль ученика сбрасывает школа в его карточке. Для других ролей отдельный интерфейс восстановления пока не реализован.

Существующая **Cloudflare-сборка** сохранена и компилируется. Она не превращает Node SQLite в D1: полноценная LMS на Workers потребует подключения command/private-data service и файлового адаптера. Не деплоить текущую SQLite-конфигурацию как якобы готовую Workers LMS. Для работающего автономного сервера подготовлен и проверен Node-target.

## Что ещё требует владельца или отдельной интеграции

- Название, контакты, подтверждённая биография/фото преподавателя, цены и расписание, реквизиты, юридические документы и права на реальные материалы. Временные значения централизованы в `spanish/const/object/school-config`, доступны редактируемые настройки `/staff/settings`.
- Реальный архив и mapping его фактического реестра. Предпросмотр и импорт fixtures не означают содержательную обработку архива или проверку прав.
- Почта, платёжный провайдер, автоматическая генерация видеовстреч, внешнее файловое хранилище и антивирусное сканирование не подключены. Интерфейс честно показывает состояние. Оплата заменена заявкой и ручным назначением.
- Редактор блоков/упражнений пока JSON, не визуальный конструктор. Модуль добавляется через UI; порядок уроков редактируется числом. Расписание показано удобным списком, без дополнительной календарной сетки. Интерфейс русский, учебный контент испанский; полная локализация кабинета не реализована.
- Production-модель сейчас односерверная Node/SQLite с раздельными файлами. Размещение персональных данных и юридическая готовность не утверждаются без решения владельца. Масштабирование на несколько серверов, внешние D1/PostgreSQL/S3 адаптеры и production-нагрузочное тестирование — отдельная работа.

## Точка продолжения

Локальная рабочая версия реализована; сквозной процесс, интерфейсы и импорт доступны. Следующий шаг владельца — открыть сайт, проверить сценарии ролей и заменить временные сведения. Следующий технический этап по необходимости — визуальный редактор и production-интеграции под выбранный хост.
