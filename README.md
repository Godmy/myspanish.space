# Испанский для всех · myspanish.space

Онлайн-школа испанского языка для детей и всей семьи. Проект объединяет публичный
сайт школы, запись на знакомство, учебные кабинеты и инструменты преподавателя
и администратора.

**Первая версия сайта — `v1.0.0`.** Основной сайт опубликован 10 ноября 2026 года;
релиз оформлен 11 ноября 2026 года.

- **Production:** https://myspanish.space
- **Preview:** https://myspanish-school-preview.pavarenkinda.workers.dev
- **Локальная разработка:** http://localhost:5176
- **Контакт школы:** mamaespanola@gmail.com

## Состав первой версии

### Публичный сайт

Лендинг представляет школу через семейный подход, живое общение и постепенное
освоение языка. Для детей 4–7 лет описана авторская программа погружения через
игру, песни, движение и творчество. Для родителей предусмотрена обратная связь
о продвижении ребёнка.

На сайте представлены шесть направлений:

1. Дети 4–7 лет.
2. Школьники и подростки.
3. Испанский для взрослых.
4. Практика с носителями из Боливии и Эквадора.
5. Испанский для переезда.
6. Материалы для совместных занятий дома, включая «Испанский с мамой».

Лендинг содержит историю основательницы Марины, описание форматов и условий,
ответы на вопросы, контакты и форму записи. Карточка направления передаёт выбор
в форму. Заявка сохраняется на сервере; время знакомства школа согласует отдельно.
Форма проверяет контакт и согласие, ограничивает частоту отправок, использует
honeypot и ключ повторной отправки. При ошибке введённые данные сохраняются.

Оформление включает семейный герб, главную фотографию преподавателя, общее фото
команды, адаптивные изображения, favicon для браузеров и устройств, web manifest.
Страницы документов используют шапку, мобильное меню и подвал лендинга;
ссылки навигации возвращают к соответствующим разделам главной.

### Документы

В сайт включены четыре документа с реквизитами ИП Паваренкиной Марины Анатольевны
и контактным email школы:

| Адрес | Назначение |
| --- | --- |
| `/legal/privacy` | Политика обработки персональных данных |
| `/legal/consent` | Согласие на обработку персональных данных |
| `/legal/terms` | Условия оказания услуг |
| `/legal/refund` | Условия отмены и возврата |

Тексты, версия согласия и реквизиты находятся в данных домена `spanish`.
Версия согласия фиксируется при отправке заявки. Юридическое согласование
и последующие изменения текстов остаются ответственностью владельца школы.

### Учебные кабинеты

В исходниках реализованы следующие роли и возможности; доступ к ним зависит
от созданных пользователей, связей и назначений в конкретном окружении:

| Роль | Возможности |
| --- | --- |
| Ученик | Назначенные курсы, уроки, упражнения, прогресс, домашние задания, комментарии преподавателя, расписание, материалы и профиль |
| Родитель | Просмотр обучения и работ связанных детей |
| Преподаватель | Ученики и группы, свои курсы и уроки, назначения, проверка работ, расписание, библиотека и назначенные заявки |
| Администратор | Настройки школы, пользователи и связи, заявки, назначение преподавателей, управление учебным содержимым и библиотекой |

Уроки поддерживают текст, изображения, аудио, видео и вложения. Есть семь типов
упражнений: один ответ, несколько ответов, пары, пропуск, порядок, карточки
и свободный ответ. Ключи закрытых упражнений проверяются на сервере.
Редактор учебного содержимого использует структурированные JSON-блоки.

Публичные примеры уроков доступны без регистрации. Закрытые работы и файлы
проверяют права пользователя на сервере. Создание реальных учётных записей,
назначение курсов и перенос учебного архива выполняются отдельно от публикации
первой версии лендинга.

## Технологии и репозитории

- Node.js **24.11+**, Yarn **4.13.0**.
- SvelteKit 2, Svelte 5, TypeScript, Vite 8.
- Cloudflare Workers, SQLite Durable Objects, Wrangler 4.
- SQLite и закрытые файлы для автономного Node-варианта.
- Общая компонентная библиотека `stylist-svelte`, подключённая через Yarn portal.
- Node test runner и Playwright для проверок.

Приложение и библиотека находятся в разных Git-репозиториях. Модули библиотеки
тоже могут быть отдельными репозиториями. Из каталога приложения зависимость
`portal:../../stylist-svelte` обращается к исходникам соседней библиотеки:

```text
cloudflare/
├── myspanish.space/
│   └── myspanish.space/               # этот репозиторий приложения
└── stylist-svelte/
    └── modules/
        ├── business/spanish/           # композиции и данные испанской школы
        └── prototype/prototype-school/ # общие интерфейсы школы и кабинетов
```

Для сборки нужны библиотека и её используемые модули, включая доступ
к соответствующим приватным репозиториям. Источники модулей разрешаются через
`modules.json` и `scripts/prepare-module-sources.mjs`; генерируемые экспорты
библиотеки вручную не редактируются.

Версии исходников библиотеки, использованные при первой публикации:

| Репозиторий | Ревизия |
| --- | --- |
| `stylist-svelte` | `c2cbc5f9c41f9665d580733420ffb3d2a17b37b9`, ветка `spanish-school-preview-2026-11-10` |
| `stylist-svelte/modules/business/spanish` | `624be70affe4d500f60fbcc38aeb42b21a57e85b` |
| `stylist-svelte/modules/prototype` | `a07803ec7c905475e3c8986527ae9f9b4dd5c5e5` |

Остальные модули восстанавливаются по gitlinks указанной ревизии библиотеки.
Ревизию `spanish` из таблицы необходимо выбрать отдельно: она содержит обновление
шапки документов после родительского коммита библиотеки. Тег приложения не
фиксирует состояние внешних portal-зависимостей автоматически.

## Окружения и хранение данных

| Окружение | Runtime и данные школы | Вход |
| --- | --- | --- |
| Production | Worker `myspanish-space`; отдельный SQLite DO `SchoolProduction`, binding `SCHOOL`, экземпляр `school-v1` | Только логин и пароль |
| Preview | Worker `myspanish-school-preview`; отдельный SQLite DO `SchoolPreview`, binding `PREVIEW_SCHOOL`, экземпляр `school-v1` | Логин/пароль; тестовые роли требуют внутреннего preview-разрешения |
| Обычный localhost | Vite / Node; `.school-data` по умолчанию | Обычная форма логина и пароля |
| Браузерный тестовый стенд | Vite / Node, порт 5187; отдельный временный каталог в `.test-data` | Явно включённые тестовые роли |
| Автономный Node production | Node adapter; отдельный `SCHOOL_DATA_DIR`, по умолчанию `.school-production` | Логин и пароль; demo-база отклоняется |

У production и preview разные namespaces: заявки, пользователи и сессии между
ними автоматически не переносятся. Production не создаёт тестовые аккаунты,
не обслуживает `/__preview/*` и игнорирует preview-cookie для тестового входа.
Обычный localhost также скрывает карточки ролей; для специального development
preview требуется `SCHOOL_PREVIEW_AUTH=true`. В production этот флаг не действует.

В Node-варианте данные разделены на `site.sqlite` (настройки и воронка),
`school.sqlite` (обучение) и `pd.sqlite` (пользователи, контакты, сессии и работы).
Файлы хранятся в подкаталогах `files` и `uploads`. Cloudflare-адаптер использует
SQLite DO и хранит вложения частями в его таблицах.

В production-конфигурации сохранены прежние bindings D1, KV и R2. Их наличие
не означает перенос школьных данных в D1 или учебного архива в R2.
Новая школьная модель использует binding `SCHOOL`.

## Локальный запуск

Предполагается, что соседняя библиотека и нужные модули уже получены и их
зависимости установлены. Команды выполняются из каталога приложения:

```powershell
cd D:\2026\cloudflare\myspanish.space\myspanish.space
yarn install --immutable
yarn dev
```

Открыть http://localhost:5176. Из корня рабочего workspace есть shortcut
`yarn myspanish`. Порт фиксирован (`strictPort`): если экземпляр уже запущен,
используйте его. Сервер запускает владелец workspace.

Первый локальный запрос создаёт development-данные. Путь хранения меняется через
`SCHOOL_DATA_DIR`. Базы, пользовательские файлы, секреты, `.env`, `.dev.vars`
и служебные каталоги не включаются в Git. UI читает исходники библиотеки напрямую;
пересборка `stylist-svelte/dist` для этого не требуется.

## Команды проверки и сборки

| Команда | Назначение |
| --- | --- |
| `yarn check` | SvelteKit sync, диагностика Svelte и TypeScript приложения |
| `yarn check:worker` | TypeScript-проверка Cloudflare-кода |
| `yarn test` | Проверки школьной бизнес-логики |
| `yarn test:preview` | Проверки архива, Cloudflare SQL-адаптера, доступа и школьных сценариев |
| `yarn test:e2e` | Браузерные сценарии на отдельном локальном стенде |
| `yarn test:preview:remote` | Проверки опубликованного preview с внутренним разрешением |
| `yarn build:preview` | Общий production-артефакт SvelteKit для текущих Cloudflare entry points |
| `yarn build:node` | Автономная Node-сборка |
| `yarn test:production` | Проверки автономного Node-хранилища; не проверка опубликованного Cloudflare-сайта |

`build:preview` создаёт `.svelte-kit-school-preview/cloudflare` с `dev=false`.
Его название историческое: артефакт используют оба актуальных Cloudflare
окружения, а поведение и данные определяются entry point и bindings.

## Публикация

Команды выполняет владелец или агент по его явному поручению после проверок.
Нужна авторизация Cloudflare с правами на соответствующие ресурсы.

```powershell
# Проверки перед публикацией
yarn check
yarn check:worker
yarn test:preview

# Выбрать нужное окружение
yarn deploy:preview
# либо
yarn deploy:production
```

| Окружение | Конфигурация | Entry point |
| --- | --- | --- |
| Production | `wrangler.production.jsonc` | `cloudflare/production-entry.ts` |
| Preview | `wrangler.preview.jsonc` | `cloudflare/preview-entry.ts` |

`deploy:production` сохраняет удалённые переменные через `--keep-vars`.
На production `www.myspanish.space` перенаправляется на `myspanish.space`.
Публичный лендинг доступен индексации; кабинеты, вход и документы имеют свои
ограничения индексации. Preview добавляет общий `noindex` и preview-заголовки.

После публикации проверяются главная, документы, изображения, обычный вход,
запрет тестового `userId` и отправка заявки. Обновление кода не является переносом
базы. При изменении схемы и откате необходимо сохранять namespaces и данные.
Подробности — в [PRODUCTION.md](docs/PRODUCTION.md).

В проекте также сохранены `wrangler.jsonc`, `wrangler.toml`, команда `yarn deploy`
и ручной GitHub workflow прежней публикации Pages. Для выпуска этой версии
используются явные команды `deploy:production` и `deploy:preview` из таблицы выше.

## Автономный Node-вариант

Для отдельного Node-сервера предусмотрены `production.env.example`,
`yarn db:school:migrate`, `yarn user:create`, `yarn build:node` и `yarn start:node`.
`user:create` работает с выбранной локальной SQLite-базой и не создаёт пользователя
в Cloudflare DO. Пример окружения заполняется для конкретного хоста;
Node не загружает `production.env` автоматически.

Для Node-размещения нужны постоянный приватный диск, корректный `ORIGIN`, TLS
и reverse proxy. Согласованная резервная копия включает все три базы и файлы.
Инструкции — в [HANDOFF.md](docs/HANDOFF.md) и [TRANSFER.md](docs/TRANSFER.md).

## Контент, архив и границы релиза

Бренд, тексты, направления и FAQ задаются в
`stylist-svelte/modules/business/spanish/const/object/school-config/index.ts`;
документы — в `spanish/data/json/school-legal-documents/index.json`.
Сохранённые настройки конкретного окружения могут переопределять значения по
умолчанию. Разметка лендинга и публичных страниц находится в `school-home`
и `school-view` домена `spanish`, общие интерфейсы — в `prototype-school`.

Проект содержит инструменты импорта реестра учебного архива и работы с библиотекой.
Ранее подготовленный реестр описывает 4 704 записи, 30 программ и 16 черновых
занятий. Это сведения об импорте, а не утверждение о наличии этих курсов и всех
вложений в production. Персональные работы исключаются из общего preview;
права и готовность материалов проверяются отдельно. Состав и формат импорта —
в [ARCHIVE-DATA.md](docs/ARCHIVE-DATA.md).

В первой публикации не подключены автоматическая отправка email, онлайн-оплата
и автоматическое бронирование видеовстреч. Форма сохраняет заявку; школа
связывается с человеком и согласует время. Цены, расписание, реальные учётные
записи, наполнение курсов и перенос архива настраиваются отдельно.

Дополнительные эксплуатационные документы содержат историю предыдущих этапов.
Для текущих адресов, правил входа и production-конфигурации используйте этот README
и [PRODUCTION.md](docs/PRODUCTION.md); устройство демонстрационного стенда описано
в [PREVIEW.md](docs/PREVIEW.md).
